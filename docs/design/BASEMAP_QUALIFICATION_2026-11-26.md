## Separation and recommendation

Keep immutable basemap context, versioned property geometry, frozen investigation and rendering separate. Recommend a small version-pinned Protomaps regional PMTiles archive, served locally/same-origin first after explicit bounded download approval. An archive is a tiled data format, not a hosting service. No need to replace MapLibre or add a geocoder. A contemporary basemap is contextual only, not evidence of historical sale-time roads/buildings/amenities. Never overlay the virtual display points or centroid schematic on a physical map. Private dossier stays geometry-withheld until field-specific rights, as-of, precision, owner isolation and release gates clear.

## Primary-source findings (reviewed 26 November)

- [Protomaps downloads](https://docs.protomaps.com/basemaps/downloads) and [CLI](https://docs.protomaps.com/pmtiles/cli): published archives and regional extraction; produced-work ODbL with OpenStreetMap attribution. No download performed. Pin exact build date/schema, archive extent, digest, data notices and extraction command before any approved experiment.
- [Protomaps data licence](https://github.com/protomaps/basemaps/blob/main/LICENSE_DATA.md), [code and style licence](https://github.com/protomaps/basemaps/blob/main/LICENSE.md), [assets repository](https://github.com/protomaps/basemaps-assets), [OSM copyright](https://www.openstreetmap.org/copyright): distinguish data/produced work, code/style, font/sprite licences. Retain applicable notices and visible linked attribution; review actual version inputs and redistribution/share-alike duties. Do not combine restricted property records into the OSM archive.
- [MapLibre basemap assets](https://docs.protomaps.com/basemaps/maplibre): actual style, tiles, glyphs and sprites must be aligned; no CDN dependence. [Cloud storage](https://docs.protomaps.com/pmtiles/cloud-storage): HTTP Range and appropriate CORS where cross-origin; every range read may be an object GET. [Privacy](https://docs.protomaps.com/guide/security-privacy): account for every external asset; same-origin CSP and HTTPS; a separate origin may reveal viewport, IP and timing, even without explicit parcel IDs.
- [OSMF raster policy](https://operations.osmfoundation.org/policies/tiles/) and [vector policy](https://operations.osmfoundation.org/policies/vector/): best-effort, service-specific use rules, identification, attribution, cache and browser referrer; not an unlimited tile service. No policy relaxation, referrer change, tile request or public autocomplete. [MapTiler terms](https://www.maptiler.com/terms/cloud/) and [pricing](https://www.maptiler.com/cloud/pricing/): free limited to noncommercial and commercial-product R&D, quota pause, provider logo, no billing information for Free. No commitment.
- [R2 pricing](https://developers.cloudflare.com/r2/pricing/) Standard monthly free tier: 10 GB-month, 1m Class A, 10m Class B, direct egress free. Beyond: USD 0.015/GB-month, USD 4.50/million A and USD 0.36/million B; billable rounding. [Budget alerts](https://developers.cloudflare.com/billing/manage/budget-alerts/) informational only, no usage cap. No guarantee of R0, taxes, account aggregate use, other service charges or provider terms. Do not create account/bucket/worker or enable billing. Pricing may change.

## Illustrative cost exposure, not measured demand

Assume 200 range GETs per viewing session, no cache savings, 0.5 GB-month storage, 100 Class A operations, no other account usage. 1,000 sessions = 200k B; 10,000 = 2m B; 50,000 = 10m B; 100,000 = 20m B -> USD 3.60 B overage alone. At 20 GB-month storage -> USD 0.15 storage overage alone. Free allowance depends on account aggregation, actual operations and billing units; a public endpoint can be abused. Local loopback proof uses no new hosted resource. Do not assume a hard cap from alerts.

## Bounded next gate and qualification tests

1. Before external download: owner approves precisely bounded regional public basemap extract (not property source extraction), release/version, extent/zoom, byte ceiling and temporary storage/disposal. Candidate only: township 17 pilot surroundings, contextual city/region zooms; exact bounding box and size TBD from public metadata, no download yet. No new provider account. Prefer first testing protocol, local range serving and asset allowlist with code-generated fictional bytes/tiles in disposable CI.
2. After approval: record archive/asset manifests, checksum, version, licence and attribution. Test one local archive and local fonts/sprites; validate compatible pinned PMTiles adapter, no global CDN, strict same-origin and no arbitrary URL/protocol. Do not put archive into Git history or existing backup storage without explicit capacity/rights decision.
3. HTTP test valid single Range 206/Content-Range, correct byte bounds/length, 416 unsatisfiable, no unbounded full-body fallback, immutable version/ETag, no redirect to external origin, no traversal or private record leak. Limit request and file sizes. Verify actual archive metadata, min/max zoom and bounds. Fail closed if invalid/missing. Separate public contextual assets from owner-protected property routes; no access to raw source records.
4. Map UX: Atlas label legibility, attribution visible at 320px and desktop, zoom/fit, selection unchanged, bounded pan, no real marker on fictional geometry, fallback for invalid archive/assets/GPU/network. Test keyboard, axe, reduced motion, no external requests. Record first-map timing, transferred bytes/range count and optional bundle impact. No live deployment, no field performance claim.
5. Production decision only after geometry field rights/as-of/privacy, measured archive costs/capacity, hard service limits and access controls, approved hosting and release. Retain existing no-geometry mode. Do not conflate G4 research with G4 actual implementation or G6 release acceptance.
