## Library selection
- Base UI: unstyled React primitives, MIT, compatible with plain CSS/CSS Modules/Tailwind. Leading compatibility-spike candidate for dialog, popover, tabs, combobox and menus. [About](https://base-ui.com/react/overview/about), [styling](https://base-ui.com/react/handbook/styling), [accessibility](https://base-ui.com/react/overview/accessibility).
- Radix: established composable unstyled primitives; viable alternative, not an additional overlapping dependency. [Introduction](https://www.radix-ui.com/primitives/docs/overview/introduction).
- React Aria: unstyled accessible interactions, localization and complex inputs; alternative for keyboard/locale-sensitive workflows. [Quality](https://react-aria.adobe.com/quality).
- shadcn/ui: editable component source distribution, not a substitute for a unique visual identity. [Introduction](https://ui.shadcn.com/docs), [July 2026 Base UI default](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default). Adapt select patterns, not entire themes. Evaluate one primitive foundation, not all three.
- CSS variables + scoped CSS/CSS Modules: preferred initial token implementation to avoid wholesale migration. [Tailwind v4 theme variables](https://tailwindcss.com/docs/theme) optional if measured component consistency/developer benefit justifies build changes; avoid mixed duplicate global systems.
- Native semantic tables for 3–5 comparable sales and two/three-property comparisons. [TanStack Table](https://tanstack.com/table/v8/docs/overview) only if saved-record complexity needs advanced filtering/sorting/pagination. Never sort evidence in a way that obscures original server rank.
- [Lucide React](https://lucide.dev/guide/react/getting-started): candidate coherent line icons, named imports, text labels for meaning, accessible names for icon-only actions.
- Native CSS for short state changes; [Motion](https://motion.dev/docs/react-use-reduced-motion) only for justified complex transitions with reduced-motion support.
- Native SVG/HTML for simple evidence plots; [Recharts](https://recharts.github.io/api/ScatterChart/) candidate for reusable React charting, [ECharts](https://echarts.apache.org/handbook/en/best-practices/aria/) alternative for later richer data. Chart semantics, keyboard usability and exact-value table still application responsibilities. Do not add graphs to make sparse sales appear predictive.
- Existing Playwright and axe first; [Storybook](https://storybook.js.org/docs/writing-tests/accessibility-testing/) optional if a component catalogue grows enough to warrant additional dev tooling. Prefer a small fixture-only review gallery initially. No external CI services needed.
All dependencies remain proposals pending lockfile/peer compatibility, license/NOTICE review, bundle and CSP checks, actual browser behavior, and R0 approval boundary. No version claimed compatible without spike.

## Design foundations and two candidate themes
Shared roles: canvas, surface, text, secondary text, border, control border, primary action/foreground, focus, selected, supported/caution/unavailable/error. Map subject/comparable/selected/unsupported are distinct from evidence states; use labels and symbols in addition to colour. Candidate palettes: Editorial Atelier canvas #F4F0E8, ink #203D34, secondary #4D5D56, action #245F4F, white surface, decorative brass #B69A69; Intelligence Studio canvas #F4F6F9, ink #182D43, secondary #53667A, action #28549A, white surface. Neither approved. Brass is decorative only; control outlines need contrast-tested distinct tokens. Supported text #315E49 on #EAF4EE, caution #805119 on #FFF4DC, error #8B3030 on #FFF4F4. Never use supported status to imply a good purchase.
Computed WCAG relative luminance ratios (opaque colour pairs, not rendered page audit): legacy #79897F on white 3.69:1; root #687A70 on #F7F7F2 4.24:1; private #A9BACB border on white 1.99:1; private #53667A on white 5.92:1; #182D43 on #F4F6F9 12.97:1; white on #28549A 7.43:1; editorial #203D34 on #F4F0E8 10.39:1; #4D5D56 on #F4F0E8 6.13:1; white on #245F4F 7.43:1; brass on ivory 2.36:1. Status pairs above 6.60/6.18/7.61 respectively. These identify candidate fixes for normal text and necessary component boundaries, not actual WCAG conformance. [WCAG 2.2](https://www.w3.org/TR/WCAG22/).
Type trial: 40/48 display, 32/40 page, 24/32 section, 18/26 card, 16/24 body, 14/20 UI/table, 12/18 secondary metadata only; rem units and responsive clamp. Trial Inter (SIL OFL, tabular numbers) for analysis; editorial serif candidate for display only. Keep existing system-font fallback; self-host only after licence and static asset allowlist review. [Inter](https://rsms.me/inter/), [USWDS typography](https://designsystem.digital.gov/components/typography/). Use tabular numerals, right align exact money and comparable numbers. No truncating cents. Use 4/8/12/16/24/32/48/64 spacing, 8–12px radii, restrained elevation. [USWDS tokens](https://designsystem.digital.gov/design-tokens/).
Layout: responsive app shell with quiet navigation, bounded content width, clear one-primary-action hierarchy; dossier desktop map/evidence split and mobile evidence/map switch. No forced card grids for every fact, no full-width repetitive buttons, no tiny labels. Critical information never only in tooltip. Motion trial 120–220ms for disclosure, selection and meaningful state change; avoid animated metrics, decorative parallax, and forced movement on reduced-motion settings.

## Reusable component and state inventory
Foundation: Button (primary/secondary/quiet/destructive; pending/disabled), Field/FieldError, SearchCombobox (only if API supports results; no fictitious autocomplete), Dialog, Tabs, Popover, IconButton, StatusMessage, EmptyState, Skeleton, Table, PageHeader, Nav, session-expired view.
Domain: PropertySearch, CandidatePicker, BuyerInputs, EvidenceStatus, PropertySummary, RankedSaleTable/Card, EvidenceExplanation, SourceDisclosure, GeographicPanel with linked selection, SavedRecordList, ComparisonTray, ComparisonMatrix, NotesEditor. Labels from approved data or neutral fallback, never invented property identity. No UI computation changes frozen evidence.
State matrix: empty/returning workspace, pending/search/no match/ambiguous, field invalid, create success/failure, supported/exploratory/insufficient/out-of-coverage evidence, geometry unavailable/GPU or network failure, stale response ignored, comparison 0–3 with duplicate/refusal, unsaved note, save failure/recovery, expiry/logout. Preserve drafts across views where allowed; clear buyer data on sign-out. Never show old sale evidence after failed new search, or fictional data as private-service fallback.
Screen sequence: sign in -> workspace -> property enquiry -> dossier -> save/shortlist -> comparison -> reopen. Two complete high-fidelity concepts use identical fictional task and data, including no-evidence and mobile states. Signature dossier prioritises property, asking price provenance, evidence count/quality and next action; map is conditional. Human-readable record selection, not UUID entry. Compare same attributes with notes and caveats, not automated winner.
