## Finding: one bundle, two application roots
frontend/react/src/main.tsx selects PrivateBetaRehearsal for /private-beta-rehearsal and BuyerWorkflow otherwise. BuyerWorkflow is the richer synthetic fixture workflow, with navigation, history, methodology, selected sale and optional MapLibre; private root is the actual provider/Neon-qualified historical-shape contract. Neither is the approved final experience. Do not copy the fixture API into the private root or bypass its projection. The server decides permitted mode. Shared presentation must not imply interchangeable service contracts.

## Proposed shared presentation boundary
Use separate strict wire decoders and typed service adapters for original synthetic and private historical modes. Never normalize by fabricating required PIN, address, snapshot IDs or geometry. Use discriminated union/capabilities established from trusted server mode, not query flags. Proposed shared fields: investigation ID, evidence status, analysis date, exact asking-price string or null, buyer area (number or null), ranked comparable facts (price string, date, age, area difference, location evidence; assessment area/year where supplied), provenance with source/build and optional permitted fields. Private result's buyer_reported_area_sqft is already supplied but not rendered as part of current typed result. Private provenance flags must remain visible. UI rank key may be investigation ID + rank, not identity of another parcel. Optional property title from approved server value or explicit neutral fallback. Unsupported status explanation must not claim exact rejection cause when no reason supplied.

Proposed operations: search, investigate, list saved metadata, reopen investigation, create comparison, reopen comparison, sign out (where applicable). Optional capabilities: candidate resolution, mutable persisted shortlist, geometry, human-readable label, source details. Preserve response version, source kind, exact count/rank, money, ownership and immutable evidence. No raw source JSON or PIN/doc IDs in private UI; no unsafe browser-only authorization. Do not call fixture endpoints if private endpoint fails. No new backend framework, no duplicate production root, no schema migration required for initial shared presentation.

## State and quality design
One active view, current investigation, selected rank, comparison draft, pending operation and recovery state. New enquiry invalidates stale result/token; cancel obsolete reads with AbortController or generation checks. Guard non-idempotent writes against double submission; ambiguous write outcome requires list/reopen reconciliation rather than blind retry. Keep note drafts across navigation; logout clears all private state only after confirmed server revocation. Error wording must not disclose credentials/IDs or raw backend errors. Distinguish empty list, unavailable list, no match, ambiguous, insufficient evidence, out of coverage, missing geometry, expired session and unavailable service. No current valuation. Source list metadata can be stale; reopen through canonical verification.

2. Implement typed adapters, contract fixtures and capability handling. Verify private strict decoder, source-kind separation and exact price.
3. Converge navigation and dossier; list/reopen and atomic comparison through private routes, preserve richer fixture behavior. Add read-only comparison state and draft safeguards.
4. Verify representative browser journeys in disposable CI: owner isolation, CSRF, stale response, no synthetic fallback, no geometry, exact cents, notes/reopen, logout, keyboard/reflow and visual screenshots. Only then consider retiring technical rehearsal UI; no main merge.
5. Separately evaluate authorised geography, persistent labels and comparison editing; no scope expansion by prototype.
