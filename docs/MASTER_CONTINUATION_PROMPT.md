# House Price Intelligence | Master Continuation Prompt v2.1

Stable operating protocol, not a live status ledger. Repository: https://github.com/Sonkhe-Shongwe/house-price-intelligence. Permanent working branch development; stable main.

## Restore progressively

1. Resolve both heads via GitHub. Pin restoration reads to exact development HEAD and inspect exact-head Actions (push and PR, including failed, pending, missing and skipped). Older success or empty status is not current success. Check local changes only with actual checkout access; disclose unknown Windows state.
2. Read [AGENTS.md](../AGENTS.md), this protocol and [checkpoint](CHECKPOINT.md). Parse its single versioned JSON routing block; schema v2 adds validated read_ranges. If invalid, missing or materially contradictory, inspect relevant evidence before choosing work; do not guess.
3. Read checkpoint task read_ranges at exact HEAD using their inclusive line bounds; confirm the first/last markers against returned text. Retrieve all listed ranges before task selection, expand to relevant sections and full applicable contracts for uncertainty or exceptional authority. If ranges drift, re-resolve against current source and repair them before proceeding. Range hints do not override source authority. Always inspect applicable [decisions](DECISIONS.md), [P0-P8 roadmap](P_PHASE_ROADMAP.md) exit criteria and estimates, and relevant [lean directive](engineering/LEAN_ENGINEERING_DIRECTIVE.md). Read the full applicable contract for consequential changes. Use [index](DOCUMENTATION_INDEX.md) for complete document discovery, not mandatory wholesale context. P0 follows [P0 directive](engineering/P0_DISCOVERY_AND_FEASIBILITY_DIRECTIVE.md); frontend work follows [Professional Frontend Excellence directive](engineering/PROFESSIONAL_FRONTEND_EXCELLENCE_DIRECTIVE.md).
4. Retrieve historical evidence only for selected decisions, disputed claims, dependencies, approvals or failed checks; retain exact source, run, date and negative findings. Inspect source/tests/workflows before editing. Do not restart completed work from dated handoffs.

Authority by category: applicable current owner direction; decision register for approval; roadmap for gates/weights/estimates; checkpoint for routing; contracts for requirements; exact source and observed runs for evidence. Archives are not authority to act. Resolve conflicts by scope, evidence and date; stop for unresolved material permission conflict. Audit research phases 0-2 are not delivery P0-P8.

## Standing engineering autonomy

Ordinary scoped research, edits, synthetic tests, CI diagnosis, corrections and commits on development delegated. No separate approval for reversible scoped work. Use one active phase; dependencies must resolve named criteria. Select checkpoint task (or narrower owner request); define requirement, evidence, smallest useful outcome, verification and stopping condition. Apply approved eight-step lean lifecycle proportionately; include meaningful failure/abstention tests. Prefer working integrated software or concrete discovery evidence in P0 over repeated planning. Preserve accepted behaviours, including the two-to-three-property shortlist. Compare retain/refactor/replace when evidence warrants; material architecture/scope changes require applicable approval.

## Approval and data boundaries

Strict R0. Generic continue, passed tests, old one-time permissions and checkpoint entries are not exceptional approvals. Check decisions and relevant contract, exact scope, target, expiry/consumption. Stop before new acquisition/live data dispatch, real intake/disclosure, material joins, contact, credential/access/provider changes outside delegated scope, spending, destructive operations, scheduled cloud changes, scope/market or acceptance changes, valuation/model training, release/deployment, exceptional branches or main integration. Every email requires exact recipient, subject, body and attachments shown and explicitly approved. Read-only metadata discovery, synthetic CI and scoped development administration remain delegated. No replay of consumed permissions. No secrets, raw property rows, private source/derived data or personal information in public Git/CI. Source-specific rights, retention, privacy and protected storage govern real use. Direct legitimate access first; separate permanent Windows HPI-Data-Workspace and Git checkout. Download access is not reuse permission. Never force-push or overwrite unknown local changes.

Separate asking price, completed sales and model estimates. Preserve earlier-only sales, unique comparable PIN, supported class, geography expansion, provenance, insufficiency and price-free matching/ranking. Exploratory 2 km evidence not valuation. Prediction conditional post-MVP.

## Execute and verify

Follow [cloud-first workflow](engineering/CLOUD_FIRST_WORKFLOW.md). Recheck HEAD before writing; commit minimal coherent changes to development without force. Run focused tests, python tools/check_docs.py and relevant integrated suites; inspect exact-head Actions and actual job results, diagnose failures without suppressing tests or weakening gates. Distinguish source implementation, synthetic verification, actual source observation, runtime integration, browser acceptance, deployed/permitted use and independently evaluated predictions. No invented local/live evidence. No live extraction for docs changes or main merge without authority.

## Checkpoint and stop

Update affected canonical records only at meaningful milestones. Keep checkpoint JSON and concise evidence together; refresh task range bounds and boundary markers when their source moves; retain substantial dated evidence in relevant existing reports, archives or immutable Git revisions. Explicit task ID, status, objective, scope, acceptance, reads, evidence and stop rule. Separate blocked phase gates from ready read-only tasks. Query HEAD and CI instead of freezing them in the protocol. Reconcile roadmap numbers only at owner-authorised evidence-based milestone review; no automatic credit per commit or test.

Stop at verified bounded milestone, indispensable approval/evidence/tool blocker, exhausted useful task or session execution limit. Report incomplete status honestly; no promise of unattended execution. Report changes, checks, exact commit/run, limitations/approvals, active P-stage, roadmap-derived before/after weighted estimate and gate status, next justified task. Always provide clickable exact-revision GitHub Actions run links and the commit link in repository verification reports, including pending or failed checks; include the focused job link when available. Never substitute older passing runs for current status. Minimise owner action.
