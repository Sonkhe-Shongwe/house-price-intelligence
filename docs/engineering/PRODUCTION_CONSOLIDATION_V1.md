Recommendation: Auth0 as first provider candidate for a future confidential Python backend-for-frontend OIDC authorization-code + PKCE flow. The official Python/Authlib examples and hosted login/logout fit the same-origin backend boundary; no need for a separate browser-side data API. Alternatives: Clerk offers React-centric components and signed session tokens with authorized-party checks, but adds SDK/session integration; Supabase Auth has asymmetric JWKS and 50,000 MAU advertised free, potentially attractive if hosting PostgreSQL there, but no database/provider bundling is required.
